# 藏锋动态消耗与加番设计

## 目标

增强藏锋的使用灵活性与收益：玩家拥有至少 1 层藏锋时即可主动使用，使用时立即消耗当前全部层数，本局下一次合法胡牌获得“已消耗层数 × 12”番。

## 行为规则

- 藏锋的积攒方式与 3 层上限保持不变。
- 主动窗口保持不变：仅能在玩家每小局第一次主回合决策使用。
- 0 层时不提供主动选项；直接提交仍返回资源不足。
- 1、2、3 层均可使用。
- 使用时立即：
  1. 读取当前公开层数；
  2. 将该数值保存为回合内的已消耗层数；
  3. 将公开层数清零；
  4. 标记本局胡牌加番已武装。
- 本局下一次服务端确认合法的胡牌获得 12、24 或 36 番。
- 正式接受胡牌后清除武装状态；回合结束时普通回合状态重置会自然清除未兑现的武装状态。
- 不实现退款、返还或“未胡惩罚”分支。层数在主动使用时已经完成消费。
- 截流仍只影响尚未主动使用的公开层数；已经消费并锁定的本局加番不再属于公开充能目标。

## 状态设计

保留现有比赛级公开计数 `edge`。新增一个回合级整数状态，记录主动使用时消费的层数。现有回合级 `armed` 标记继续表示本局加番已经武装。

胡牌后的 post-legal 加番只读取回合级已消耗层数，并计算 `consumedLayers * 12`。这样候选算番、反事实归因和最终算番继续复用现有纯读取管道，不从已经清零的公开层数反推结果。

## 表现与协议

不新增协议字段或 UI 结构。现有公开层数事件会在使用时显示为 0；现有主动天赋生效反馈继续沿用。天赋描述更新为明确说明至少 1 层、消耗全部层数及每层 12 番。

## 测试

纯 C# 回归覆盖：

- 0 层不提供选项且提交被拒绝；
- 1、2、3 层都能在第一次主回合决策使用；
- 使用后公开层数立即归零；
- 三种层数分别提供 12、24、36 番；
- 候选算番不消费状态，正式接受胡牌后才清除武装状态；
- 错过首次主回合决策后仍不能使用；
- 回合结束依靠既有回合状态重置，不存在退款路径。

Unity/Tuanjie Refresh 与视觉验收不属于本次逻辑改动，由人工集成关口执行。
