# 卡组编辑器固定预算检查器设计

## 目标

将早期构筑编辑器 B 方案“当前档位单表盘”与现有卡组编辑器结合。保留现有牌张编辑、6 个主天赋槽、3 个备选槽、牌库列表和保存流程，把目前挤在顶部状态栏中的异化信息恢复为完整、始终可见的预算检查器。

本次只调整卡组编辑器的布局与编辑草稿状态，不改变异化值算法、服务端准入规则、房间档位语义或天赋装配规则。

## 布局

编辑器继续使用“中央编辑区 + 右侧栏”的整体结构。右侧栏由上至下分为两个独立区域：

1. 固定的“当前构筑预算”检查器。
2. 可滚动的牌库列表与底部“新建牌库”按钮。

右侧栏从现有约 280px 增加到约 320px。预算检查器不参与牌库列表滚动，因此编辑牌张、天赋或浏览其他牌库条目时始终可见。中央牌张与天赋编辑区域不增加新的固定列。

中央顶部删除现有异化进度条、左右档位箭头和拥挤的成本说明，仅保留牌数、清空和重置。保存与退出按钮继续位于中央编辑区底部。

## 预算检查器

预算检查器按以下顺序展示：

- 标题“当前构筑预算”；编辑草稿发生变化后追加“未保存”。
- 当前卡组名称。
- 约 128px 的圆形表盘，中央显示精确的“当前总值 / 档位上限”。
- 三个可直接点击的档位按钮：低异化 40、标准 80、高异化 120。
- 成本拆分行：牌山成本、当前主天赋成本、备牌“不计入”、当前总计。
- 当前状态说明：可进入该档位房间，或“超限 X，仍可保存，不能进入该档位房间”。

表盘填充比例最多显示到 100%，但中央数值必须保留真实总值。低于档位上限 80% 时使用主题青色；达到 80% 且未超限时使用琥珀色；超限时使用红色。颜色只作为辅助，状态必须同时用文字表达。

备选天赋卡仍显示各自成本，但不计入当前开局预算。预算检查器明确显示“备牌不计入”，避免玩家误以为携带九个天赋会全部消耗预算。

## 编辑草稿与已保存数据

`DeckEditorToolkit` 继续以当前深拷贝的牌张配置、天赋配置和档位作为编辑草稿。预算检查器始终读取该草稿并即时重算：

- 修改牌张时重新计算牌山成本。
- 修改主天赋时重新计算主天赋成本。
- 修改备牌时保持总预算不变，但更新备牌展示。
- 修改档位时更换上限并重新判断状态。

修改牌张、主天赋、备牌或档位后，预算检查器进入“未保存”状态。下方牌库条目在保存前不跟随草稿变化，继续显示上一次保存的档位、总值和超限状态。保存成功后，草稿写回 `SavedDeck`，清除“未保存”状态并刷新牌库列表。

档位按钮修改的是当前卡组的编辑草稿，不立即写入档案。该档位与牌张、天赋一起由“保存”操作持久化。

## 离开未保存草稿

存在未保存修改时，以下操作必须经过统一确认边界：

- 选择其他牌库。
- 新建牌库。
- 删除当前牌库。
- 退出卡组编辑器。

当前牌数恰好为 34 张时，确认框提供“保存 / 放弃 / 取消”：

- 保存：保存当前草稿，再继续原操作。
- 放弃：丢弃当前草稿，再继续原操作。
- 取消：关闭确认框并留在当前卡组。

当前牌数不是 34 张时，保存仍不可用。确认框明确说明“当前牌数不是 34 张，无法保存”，只提供“放弃 / 取消”。异化值超限不影响保存选项。

确认框只负责保护编辑草稿，不修改房间准入结果，也不自动调整牌张、天赋或档位。

## 组件边界

- `DeckEditorView.uxml`：定义固定预算检查器、三个档位按钮、成本拆分、状态文字、牌库滚动区域和未保存确认框的结构。
- `DeckEditorStyles.uss`：负责右侧栏尺寸、圆形表盘、档位按钮、正常/接近上限/超限颜色，以及确认框样式。
- `DeckEditorToolkit.cs`：查询新元素、维护草稿脏状态、处理直接档位选择、统一离开确认流程，并在保存后刷新已保存牌库条目。
- `AlienationGaugePolicy`：继续作为预算数值、上限、填充比例和超限量的纯 C# 来源；不在 UI 中复制预算算法。

不新增独立 `UIDocument`、Scene Object 或网络消息。预算检查器属于卡组编辑器常驻属性面板，应继续由现有卡组编辑器文档承载。

## 异常与安全行为

- 当前卡组或天赋配置为空时，沿用现有规范化流程并安全显示零值，不因预算面板抛异常。
- 未定义的档位按现有策略回退到 Standard，不在 UI 层创造新档位。
- 超限构筑允许保存，但状态文字持续警告；创建和加入房间仍由客户端预检及服务器权威校验阻止。
- 确认框打开时应阻止对下层牌张、天赋和牌库列表的输入；关闭后立即归还输入。
- 控制器销毁时解绑新增按钮和确认框回调，避免重复绑定。

## 验证

自动验证以纯 C# 和静态结构检查为主：

- 档位 40/80/120 的预算、填充比例、80% 颜色阈值和超限量。
- 牌张、主天赋、备牌和档位分别触发未保存状态。
- 备牌变化不增加当前预算。
- 保存后清除未保存状态并刷新已保存条目。
- 未保存状态下切换、新建、删除当前牌库和退出均经过统一确认。
- 非 34 张草稿不可选择保存；超限草稿仍可保存。
- UXML 中预算检查器位于牌库滚动容器之外，三个档位按钮与成本拆分字段名称唯一。

Unity 人工验收覆盖：

- 预算检查器在牌张和天赋区域滚动时始终可见。
- 16:9 与项目支持的较窄窗口中，三个档位按钮、表盘和成本文字不重叠。
- 正常、接近上限、超限和未保存状态的颜色与文字清晰。
- 未保存确认框的保存、放弃、取消及输入拦截均正确。
- 牌库列表只在保存后更新数值，且列表滚动不移动预算检查器。

智能体不启动 Unity/Tuanjie Refresh，不编辑 `.meta` 或 Unity 生成的 `.csproj`；最终布局与点击验收由人工在 Unity 中完成。
