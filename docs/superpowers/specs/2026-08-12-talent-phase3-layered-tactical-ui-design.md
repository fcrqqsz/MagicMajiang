# Phase 3 分层战术 UI 设计补充

日期：2026-08-12

状态：设计已确认，等待文档审核

适用分支：`codex/talent-actions-ui-unified`

## 1. 目的与范围

Phase 2 已完成主动天赋、中场备牌、权威快照和正式网络命令链路。Phase 3 的首要目标是为这些能力提供可人工验收的正式 UI，并让玩家清楚感受到三种玩法收益：构筑大牌、识别并克制对手、积攒并兑现爆发。

本补充设计采用“分层战术 UI”：沿用原 Phase 3 规划的页面结构，不重做现有 UI 框架；同时纳入 Phase 2 完成后确认的新产品规则。本文覆盖并修订 `docs/superpowers/plans/2026-08-04-talent-ui-ai-feedback.md` 中以下旧假设：

- 异化值档位不再是全局的纯预览偏好，而是每套卡组保存的配置字段；
- 中场继续沿用原规划的全屏战术桌，不改为九卡统一勾选或前后方案对照页；
- HUD 采用分层密度，不让九个天赋和所有对手情报同时常驻展开；
- 结算不只展示天赋增益/压制聚合值，而要展示权威的逐天赋贡献项；
- 强反馈首期只由主动天赋成功生效触发。

Phase 3 仍使用 UI Toolkit（UXML/USS/C# controller），禁止 Canvas/UGUI。所有 UI 只消费 `ClientRoomState`、`ClientGameState` 和纯展示策略，不读取服务器 runtime，也不建立客户端权威路径。

## 2. 总体信息架构

### 2.1 卡组编辑器

沿用原来的 6 主槽 + 3 备选槽分区：

- 主槽：大 ×1、中 ×2、小 ×3；
- 备选槽：备选中 ×1、备选小 ×2；
- 重复天赋、品阶不兼容、`MainOnly` 和 `MainOnlyLocked` 限制仍在选择列表中明确表现；
- 备选天赋携带时不计入开场异化值，只有当前生效主天赋计费。

每套卡组保存一个异化值档位：Low 40、Standard 80 或 High 120。编辑器使用一根表盘显示当前卡组在其自身档位下的状态：

- 档位名称和上限；
- 当前总值；
- 牌山成本与当前生效天赋成本拆分；
- 超限数值。

切换档位会修改当前卡组配置并立即重算，而不是只修改全局预览。超限卡组仍可保存、复制、切换和继续编辑；编辑器及卡组摘要持续显示“超限 X 点，无法用于该档位房间”。保存行为不代表卡组可进入比赛。

### 2.2 创建、加入与房间展示

创建房间时房主必须指定异化值档位。服务器验证当前携带卡组：

1. 卡组保存的档位与所选房间档位一致；
2. 卡组在该档位下没有超限；
3. 原有牌山、槽位、重复 ID 和天赋携带规则全部合法。

加入房间时，服务器以房间固定档位执行同样校验。房间不会修改玩家卡组，玩家卡组也不会自动适配房间。

客户端可以提前检查并显示阻止信息，但服务器保留最终权威。失败提示必须明确展示实际差异，不自动跳转编辑器，也不自动切换卡组或档位。典型文案：

```text
无法加入房间
当前卡组档位：低异化 40
房间档位：标准 80
卡组档位与房间档位不一致。
```

超限时展示卡组当前值、上限和超出值。创建失败采用相同结构，只将标题改为“无法创建房间”。

房间内公开显示房间档位；精确构筑总值只向本家展示，其他席位不得看到。

### 2.3 牌桌 HUD

采用席位就近布局和 B 型分层密度：

- 本家生效天赋在手牌附近常驻显示；
- 本家未激活天赋和备选天赋折叠到摘要/展开层，不占用常驻牌桌空间；
- 对手已知天赋靠近对应席位，每席常驻显示两个重点或最近公开的条目；
- 其余已知条目显示为 `+N`，可展开查看；
- 本家 Chip 可显示权威 active 状态、充能、剩余次数和本局消耗状态；
- 对手 Chip 只显示已揭示身份与最后公开动态值，不显示中场后是否仍生效；
- 事件流位于牌桌侧边，最多保留最近四条实时天赋记录。

Chip 排序必须稳定。重点/最近条目的选择只基于客户端已获授权的公开事件，不得借排序或数量泄露未公开天赋。

### 2.4 主动天赋操作区

主动天赋按钮并入现有 `ActionPanel`，放在普通麻将操作上方：

- 仅显示服务器当前权威 `TalentActionOption`；
- 点击天赋不会完成或关闭普通麻将决策；
- 请求等待结果时只禁用对应天赋按钮，其他天赋和普通操作保持各自权威状态；
- `藏锋`等无目标主动天赋直接提交；
- `截流`等带目标主动天赋打开通用选择面板，内容完全来自服务端选项；
- `定心`等被动天赋不生成按钮；
- 取消目标选择只关闭选择面板，不提交请求；
- decision 结束、恢复快照、离开场景时强制关闭临时选择面板。

### 2.5 中场备牌

沿用初始规划的全屏“中场整备”战术桌：

- 顶部显示标题和 45 秒倒计时；
- 主区域分为当前生效区和 1 中 + 2 小备选卡区；
- 九张携带卡均显示“生效/停用”，点击切换本地草稿，不使用拖拽；
- 可以追加、停用或替换可切换天赋，最终生效数量不固定为 6；
- `MainOnlyLocked` 显示锁图标且不可停用；
- 实时展示本家异化值表盘、牌山/生效天赋成本和非法原因；
- 同屏显示已知对手情报，但只使用已经公开的数据，不展示其备牌或中场后 active 状态；
- 显示四席确认进度；
- 底部提供错误区域和“锁定方案”按钮。

草稿只存在于 `SideboardPanelController` 的本地状态。预算或规则明显非法时禁用锁定按钮。服务端未接受前不得更新 `ClientGameState` 的权威生效集合。

收到成功或任何 locked 结果后立即进入只读等待。服务器拒绝、超时或断线会锁回原方案，客户端丢弃草稿。重连只显示权威 `ownLocked` 和席位等待进度，不恢复未提交草稿或重新开放选择。

### 2.6 结算页

结算视觉层级固定为：

1. 最终番置顶，以最大字号作为主结果；
2. 下方展示基础番；
3. 再逐条展示每个天赋的带符号影响；
4. 更下方保留原有国标番种详细列表、手牌缩略图和继续按钮。

示例：

```text
最终番 22

基础番          8
藏锋          +16
快人一步       +2
截流           -4
```

正向和负向条目使用不同但色盲可辨的颜色、符号和文字，不只依赖红绿。未影响本次结果的携带天赋不显示。流局时隐藏整个番数拆分区域。胜者、放铳者及重连进入结算页时显示同一份服务器权威结果。

## 3. 三级反馈系统

### 3.1 组件定义

- Toast：短暂的大提示，位于牌桌上方或中央安全区域，约 1–2 秒后消失；
- Chip：天赋常驻徽章，负责显示身份、状态、充能、次数和本局消耗；
- 事件流：牌桌侧边按时间排列的最近四条天赋记录。

### 3.2 反馈等级

强反馈首期只由“主动天赋的玩法效果确实成功应用”触发：

- 显示 Toast；
- 对应 Chip 播放强调动画；
- 追加事件流；
- 播放通用主动天赋成功音效。

请求被服务器拒绝、目标失效或主动效果被防御阻挡时，不播放成功 Toast 和成功音效。防御天赋的揭示、消耗或阻挡记录按中反馈处理。

中反馈用于天赋揭示、充能变化、次数变化和控制阻挡：

- 更新并轻量强调相关 Chip；
- 追加事件流；
- 不显示中央成功 Toast，不播放主动成功音效。

弱反馈用于普通权威状态同步和没有新玩法事件的数值刷新：

- 只更新 Chip；
- 不追加事件流，不播放动画、Toast 或音效。

所有实时反馈以有序消息中的稳定事件 ID 去重。应用恢复快照时只重建当前 Chip、可用主动动作和备牌锁定状态，不重播 Toast、事件流、音效或历史动画。

## 4. 通用主动天赋占位音

Phase 3 生成并接入一份通用占位音：

- 路径：`Assets/Audio/SFX/Talent/talent_active_generic.wav`；
- 格式：WAV，PCM，48 kHz，16-bit，stereo；
- 时长：约 0.7 秒，可接受范围 0.6–0.8 秒；
- 听感：起始为清脆麻将牌碰击，随后叠加短促上扬的奇幻能量音；
- 起音响应快，不包含可感知的前置静音；
- 结尾使用短淡出，不产生爆音；
- 峰值不超过 -1 dBFS，听感响度与现有 UI 音效保持合理一致。

所有没有专属音效的主动天赋成功事件使用该资源。未来增加专属音效时，由展示层按天赋元数据选择；缺少专属资源时继续回退通用音，不修改玩法规则或协议。

音效只响应实时、去重后的“主动效果已应用”事件。点击按钮、收到 Accepted 但效果未应用、失败、被阻挡以及重连恢复都不播放。

## 5. 权威数据与协议补充

### 5.1 卡组档位

卡组存档必须携带其异化值档位。创建房间请求同时携带房间档位及当前卡组；加入房间继续携带当前卡组。服务端分别校验档位匹配和预算合法性，返回稳定错误码及可供客户端映射的结构化原因。

客户端提示不依赖解析服务器任意富文本。服务端错误码至少应能区分：档位不匹配、异化值超限、槽位/牌山/天赋构筑非法。

### 5.2 逐天赋结算贡献

胡牌结果与可恢复快照需携带：

- `finalFan`：服务器最终权威番数；
- `baseFan`：没有天赋增减时的基础番；
- 零到多个贡献项，每项至少包含稳定 `talentId`、带符号 `fanDelta` 和贡献类别；
- 贡献类别至少能区分合法性阶段增益、合法后增益和负向压制，供排序、样式与诊断使用。

显示名称由客户端 `TalentRegistry` 元数据映射，协议不发送可注入的富文本。客户端可以检查 `baseFan + Σ fanDelta` 是否等于 `finalFan` 并记录诊断，但不得覆盖服务器 `finalFan`。

贡献项使用服务端实际落账结果，不根据携带列表或客户端规则反推。相同天赋如果在一次结算中存在多个独立贡献，服务端应按设计稳定聚合为一个条目，避免 UI 出现难以解释的重复行。

### 5.3 隐私

- 本家可见完整九个携带天赋、生效状态、私有动态值和精确异化值；
- 他家只可见已经揭示的天赋与最后公开动态值；
- 中场草稿、未揭示天赋、对手精确预算和中场后 active 状态不得出现在公共消息或他家快照；
- 对手 HUD 的 `+N` 只统计本席已获知的公开条目；
- Peek 等私有信息不进入通用事件流、Toast 或遥测文本。

## 6. 错误与边界状态

- 超限卡组可以保存，但卡组摘要与编辑器持续警告；
- 创建和加入校验失败时留在当前界面，显示明确阻止原因；
- 主动天赋失败只恢复对应按钮并显示简短错误，不伪造成功反馈；
- `StaleDecision` 或 decision 结束时清空主动操作和目标选择；
- 中场非法提交按服务器既有语义锁回原方案，界面转只读，不允许重复试交；
- 中场倒计时只用于展示，真正 deadline 以服务器为准；
- 断线重连不恢复蓄力选择、截流目标选择或中场草稿；
- UI 遇到未知天赋 ID 或未知事件类型时使用安全通用文案并记录 warning，不阻断牌局。

## 7. 验收与测试

自动测试至少覆盖：

- 每套卡组独立保存 Low/Standard/High 档位；
- 超限卡组仍可保存且展示 overflow；
- 创建/加入时的档位不匹配、超限和服务端权威拒绝；
- 本家完整天赋与他家已揭示-only 投影；
- 对手 `+N` 不统计隐藏天赋，中场后不泄露 active 状态；
- 有序消息的重复、乱序和恢复静默；
- 主动按钮不关闭基础麻将动作，目标选择取消不提交；
- 只有主动效果实际成功应用才触发强反馈和音效；
- 中场草稿、锁定天赋、预算、成功、非法、超时、断线与只读恢复；
- 逐天赋结算贡献、负值样式、流局隐藏和结算快照恢复；
- 客户端诊断总和不一致时仍展示服务器 `finalFan`。

Phase 3 完成并合并回 `master` 后统一进行 Unity 与真人联机验收：

- 16:9 与项目支持的最窄分辨率；
- 一真人 + 三 AI 的主动天赋反馈；
- 至少两真人 + AI 的 HalfGame，中场同步、合法/非法提交、超时、断线和重连；
- 本家/他家天赋、Peek、异化值和备牌隐私；
- 最终番置顶、逐天赋贡献、极长国标番种列表、手牌缩略图与继续按钮；
- 通用占位音不会在点击、失败、阻挡或重连时误播。

## 8. 非目标

- 不重做大厅、牌桌或结算的整体美术风格；
- 不使用 Canvas/UGUI；
- 不为所有天赋制作专属音效；
- 不在客户端重新实现服务器天赋效果、算番或备牌权威；
- 不自动修复、切换或迁移超限/档位不匹配卡组；
- 不在 Phase 3 合并回 `master` 前宣称完成真人联机验收。
