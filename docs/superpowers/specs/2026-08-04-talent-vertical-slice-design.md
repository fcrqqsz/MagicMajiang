# 天赋玩法垂直切片与异化预算设计

## 目标

下一阶段优先验证 Roguelike 麻将的构筑爽感，而不是继续推进账号、部署和服务端持久化。首个可玩里程碑应让玩家明确体验三类策略：通过牌山和天赋做出平时难以完成的大牌、用软控制和反制影响对手节奏、跨小局蓄力后抓住时机爆发。

首期将现有 6 个天赋迁入统一运行时，并新增 3 个锚点天赋。九个天赋用于验证架构、异化预算、主动技能、跨局状态、控制反制、半场备牌和反馈链路；构筑池扩展到 18 个天赋属于后续独立设计周期。

成功标准：

- 天赋能够改变玩家决策，而不仅是结算时追加数值；
- 每场半庄出现可被玩家明确归因于天赋的高光、控制或反制时刻；
- 控制只降低天赋节奏或收益，不能删除玩家的基础麻将计划；
- 新天赋不再要求在 `GameServer` 或 `Room` 中增加按具体天赋 ID 执行效果的分支；
- 1 真人加 AI 与多真人联机都能完整体验天赋、备牌和断线恢复。

## 范围与基准

- 标准验证模式为半庄 8 局；单局通常在每家约 10 次抓牌内结束。
- 配装在进房前固定为 6 个主槽：1 大、2 中、3 小；继续支持高槽向下兼容。
- 新增 3 个备牌槽：1 中、2 小。大型天赋必须在赛前主构筑中投入。
- 半庄和全庄只在完成前 4 局后进行一次备牌调整；单局和东风局不开启备牌。
- 不包含正式账号、WSS、房间持久化、多实例部署、完整天赋脚本语言和最终美术资源生产。

## 权威天赋运行时

`Room` 持有一个贯穿整场对战的 `TalentMatchRuntime`。当前每小局创建的新 `GameServer` 接收同一个运行时引用，并只负责在明确的生命周期节点调用它。房间关闭时释放运行时，避免状态跨房间残留。

运行时管理：

- 九个携带槽、当前生效集合和不可换下集合；
- 每个天赋自己的整数层数、剩余次数、冷却、是否公开和本局使用标记；
- `Round` 与 `Match` 两种状态周期；
- 本家完整状态、他家已知情报和公开效果的投影；
- 主动天赋在当前权威决策中的可用动作列表。

扩展 `TalentRule` 元数据，至少声明品阶、异化费用、状态周期、公开策略、允许的主动窗口和备牌策略。备牌策略分为可自由切换、只能主槽且锁定、不能放入备牌。`初始资金`为只能主槽且锁定，避免获得永久分数后在半场释放预算。

运行时提供类型化生命周期：对战开始/结束、小局开始/结束、摸牌前后、出牌前后、动作校验前和算番前后。现有 `starting_capital`、`peek`、`head_start`、`dragon_ascent`、`draw_reward` 等特殊判断迁回对应规则类。`GameServer` 只消费运行时返回的效果和合法性结果，不按具体天赋 ID 分支执行效果。

### 天赋 ID 使用边界

天赋 ID 是稳定身份，不应被禁止。以下场景应继续使用 ID：注册与实例创建、元数据查询、存档和协议序列化、UI 查找、日志与测试，以及 `TalentAction` 定位本家或目标天赋实例。运行时可以使用 ID 作为实例索引。

禁止的是共享流程使用 `if/switch (talentId)` 实现具体天赋效果，或由 `GameServer`、`Room` 直接引用具体天赋类和常量。符合既有生命周期的效果留在规则类；确实需要牌局编排支持的独特效果增加最小的强类型请求或结果，不为了消除 ID 建立通用效果脚本、反射调用链或多层适配器。

首期不建立数据驱动脚本语言。规则类返回结构化效果，由运行时统一验证、应用和生成可见事件；规则类不能直接向其他席位发送网络消息，也不能绕过服务端修改客户端状态。

## 异化值预算

保留当前牌山异化算法，总异化定义为：

`牌山异化值 + 当前生效天赋的异化费用`

不可换下天赋始终属于生效集合，因此只计费一次。

备牌仅携带时不计费；半场启用后立即进入预算。停用的可切换天赋不再计费，已经产生的历史得分或公开情报不回滚。

房间使用官方预设：

- `Low = 40`
- `Standard = 80`，竞技默认
- `High = 120`

创建房间时由房主选择预设，加入者沿用房间预设。客户端只做即时预览，服务端使用重建后的可信牌山和天赋配置重新计算；超限构筑不得创建或加入房间。

具体总异化值是本家私有信息。编辑器、本家房间视图和本家恢复快照可显示当前值与上限；其他席位只知道房间预设和该构筑已通过校验。公共 `RoomSeatMessage`、广播与他家快照不得携带具体总值。

首期费用区间为小型 3–8、中型 10–18、大型 22–32。费用按可靠性、触发频率和构筑联动收益评估，不要求同品阶同价。

## 备牌阶段

完成第 4 局并结算跨局天赋进度后，`Room` 进入一次 `WaitingForSideboard` 状态，打开 45 秒的并行权威决策。玩家从赛前携带的九个天赋中提交新的生效集合，可以追加、替换或停用，但不能停用锁定天赋，且最终异化值必须不超过房间上限。

- 九个携带槽内不允许重复天赋；主槽、备牌槽和品阶均由服务端验证。
- 新启用备牌从该天赋的初始状态开始；不会补发已经错过的对战开始或小局开始效果。
- 玩家提交后不能修改；全部席位提交或倒计时结束后进入南一。
- 超时、非法提交或断线均立即锁定该席原生效集合；重连后只能看到已锁定等待状态，不能重新进入选择。
- 未提交的客户端编辑草稿不存入服务端，也不进入快照。
- 调整结果对其他玩家隐藏。已暴露天赋仍保留在“曾见过”情报中，但不标记当前是否生效；计数等动态信息停留在最后一次公开值。

## 主动技能与断线边界

主动技能只出现在已有主回合或响应决策窗口。首期三个新增天赋只使用主回合窗口。客户端提交独立的 `TalentActionMessage`，携带当前 `decisionId`、天赋 ID、目标席位和可选目标天赋 ID。

服务端校验当前决策、控制席位、截止时间、天赋是否生效、窗口、次数、资源和目标。成功释放天赋不会关闭主回合决策，玩家仍需提交正常出牌或其他麻将动作。重复、迟到、错误席位和 AI 控制期间的真人请求必须被拒绝。

目标选择和确认弹窗是客户端临时状态：

- 断线前未被服务端接受的出鞘选择、截流目标和其他临时选择直接丢弃；
- 重连只恢复当前权威牌桌状态和基础决策，例如主回合待出牌；
- 若原 `decisionId` 仍有效且真人仍掌握决策，客户端从未选择状态重新计算可用技能；
- 已被服务端接受的层数、次数和效果正常进入快照，但不重放动画或再次弹窗；
- 决策已超时或由 AI 接管时，不恢复技能输入。

## 控制与结算底线

- 天赋不能阻止基础摸牌、出牌、吃碰杠胡，不能夺取、替换、封印或使对手已持有暗牌失效。
- 天赋可以在牌进入手牌前修改下一次摸牌；修改牌必须保留 `IsModified` 和来源标识。
- 控制可以影响天赋层数、次数、冷却、公开信息和天赋结算修正，不延长操作倒计时，也不减少基础摸牌次数。
- 胡牌合法性先按基础番种和正向天赋条件确认；负向结算效果不能使已经合法的胡牌重新变成不足 8 番。
- 未来单个负向结算效果最多减少 4 番，一次胡牌累计最多减少 8 番。
- 同名持续控制不叠加强度；重复施加只刷新原始持续时间。每席同时最多承受两个负向持续效果。
- `Round` 控制在小局结束时清理；只有明确声明为 `Match` 的蓄力和次数跨局保留。

## 首批九个天赋

现有天赋保留原意与费用：

- `点金手`，中，15：摸到风牌或箭牌时变为发财；摸牌时私有，修改牌公开后才暴露来源。
- `如龙`，中，15：清龙判定允许一张牌存在 ±1 偏移；实际影响胡牌时公开。
- `快人一步`，中，12：获得 +2 天赋番并降低起胡门槛；实际影响胡牌时公开。
- `窥探`，小，5：每小局开始私下查看牌山顶部 4 张；除侦察效果外不主动公开。
- `厚积`，小，3：流局时获得 +5 分；得分时公开。
- `初始资金`，小，5：整场开始获得 +30 分；得分时公开，只能主槽且半场不可停用。

新增锚点天赋：

- `藏锋`，大，28，`Match`，开局公开：自己未获胜的小局结束时获得 1 层“锋”，最多 3 层。每小局自己的第一次主回合可以消耗 3 层出鞘；本小局下一次合法胡牌获得 +16 天赋番，未胡则加成在小局结束时消失。锋层数与出鞘状态公开。服务端额外校验这是该席本小局第一次主回合。
- `截流`，小，8，`Match`：整场对战共 3 次，每个自己的主回合最多使用一次。选择一名对手及其一个已公开、当前层数大于 0 的蓄力天赋，使层数立即减少 1，最低为 0。首次使用后公开并显示最后公开的剩余次数；即使被 `定心`抵消也消耗次数。
- `定心`，小，6，`Round`：每小局第一次受到负面天赋效果时完全抵消。触发后公开并显示本局已消耗，下一小局重置。

`点金手 + 如龙`验证大牌形成，`截流 + 定心`验证软控制和反制，`藏锋`验证跨局蓄力、公开威胁和爆发结算。

## 信息公开与 UI

大型天赋在对战开始时公开。中小天赋按具体效果决定暴露时点：改变公共分数、公共状态或直接影响他人时公开；纯私有窥探和未进入公共区域的摸牌变化保持私有，直到被侦察或其结果公开可见。

HUD 采用席位就近布局：

- 对手的大型天赋、已知天赋和公开状态贴近对应席位；
- 本家天赋条位于手牌附近，显示图标、锋、剩余次数和冷却；
- 主动技能按钮并入现有操作区，不创建额外的牌局暂停窗口；
- 触发提示写明来源、目标和变化，并进入可展开的天赋记录；
- 已知但可能在半场被换下的天赋标为“已知”，不显示启用或停用。

东四后使用独立全屏战术桌，同时显示当前生效区、1 中 2 小备牌、已知对手情报、私有异化预算、45 秒倒计时和确认人数。

牌库编辑器使用当前预设单表盘。玩家可以切换 40/80/120 预览，查看“牌山成本 + 生效天赋成本”；预览不修改构筑，最后选择的预设保存在玩家设置中并默认为 `Standard`。构筑只要牌数和槽位合法即可保存，进入房间时再按所选预设限制。

结算面板拆分基础番、天赋增加、天赋减少和最终番数，突出 `藏锋 +16` 等高光，同时避免把负向效果混入国标番种列表。

首期完成图标绑定、品阶颜色、文本后备图标和状态条能力；九个正式插画图标可在玩法验证后统一制作。

## 协议与数据兼容

网络协议升级为 v3；旧客户端在 `Hello` 阶段收到协议不匹配。玩家构筑 schema 升级为 v2，包含 6 个主槽和 3 个备牌槽。旧 `SavedDeck` 缺少备牌字段时自动补三个空槽，原六槽与牌山不变，异化值重新计算。

主要协议能力：

- 创建房间携带异化预设，加入与恢复消息返回房间预设；
- 本家私有构筑确认返回总异化值和上限，公共席位消息不返回总值；
- 主回合私有决策包含当前可用天赋动作；
- `TalentAction` 原子提交主动效果，但不消费基础麻将决策；
- `TalentEvent` 按公开、目标私有和来源私有三种可见性进入各席消息流；
- `Sideboard` 决策和提交结果进入有序消息流；快照只恢复本家是否已经锁定及当前权威生效集合，不保存候选勾选或未提交草稿；
- 快照保存权威生效集合、层数、次数、公开情报和基础决策，不保存客户端临时弹窗或备牌草稿。

使用稳定错误码区分异化超限、非法携带、天赋不可用、错误目标、次数耗尽、过期决策和非法备牌。客户端显示可理解提示，服务端日志保留具体拒绝原因。

## AI 与试玩支持

AI 使用标准 34 张牌山和按房间预算裁剪的预设九槽构筑，不再全部为空天赋。标准档初始方案应包含 `藏锋`，使单人测试也能观察公开蓄力和截流交互。

- `藏锋`达到 3 层时，AI 在本局首次主回合自动出鞘；
- `截流`选择当前层数最高的公开蓄力天赋，同层按座次稳定选择；
- 半场备牌优先启用能针对公开大型天赋的合法方案，超限时停用费用最低的可切换天赋；
- 没有合法改善时保持原方案。

AI 策略保持确定性，方便回归测试；本期不追求完整构筑博弈强度。

## 测试与验收

扩展独立 NetworkRegression，至少覆盖：

1. 牌山与当前生效天赋费用计算；锁定天赋始终留在生效集合且只计费一次，备牌携带不计费。
2. 40/80/120 创建与加入校验、篡改总值无效、九槽重复和品阶错误被拒绝。
3. 公共席位与他家快照不含具体异化值、隐藏备牌或未公开天赋。
4. `TalentMatchRuntime` 跨多个 `GameServer` 保留 `Match` 状态并清理 `Round` 状态。
5. 现有六个天赋通过生命周期事件触发；`GameServer` 与 `Room` 不存在按具体 ID 执行天赋效果的分支，但注册、协议和实例定位继续使用 ID。
6. `藏锋`未胜加层、最多 3、仅首次主回合出鞘、消耗 3、合法胡牌 +16、未胡失效。
7. `截流`整场 3 次、每主回合最多一次、只能选择公开且层数大于 0 的蓄力天赋、层数不低于 0。
8. `定心`抵消本局第一次负面效果、被抵消的截流仍消耗次数、下一局重置。
9. `TalentAction` 不关闭主回合；重复、过期、错误控制者、错误目标和 AI 控制期间的人类提交被拒绝。
10. 第 4 局后仅触发一次备牌；合法追加/替换/停用生效，超限、超时和断线保持原方案。
11. 重连恢复主回合待出牌和已确认天赋状态，不恢复出鞘/截流选择弹窗或未提交备牌草稿。
12. 天赋事件按席发送，私有窥探、牌山信息和隐藏构筑不串席。

人工矩阵覆盖 1 真人 + 3 AI、2 真人 + 2 AI、4 真人半庄；验证技能按钮、提示归因、东四备牌、超时、断线、重连、结算拆分和隐私。最终运行：

```powershell
dotnet run --project Tests\NetworkRegression\NetworkRegression.csproj --no-restore
dotnet build Assembly-CSharp.csproj --no-restore
git diff --check
```

服务端记录结构化天赋事件：装备、触发、主动使用、层数变化、控制生效/抵消、备牌调整、天赋番变化和构筑拒绝。首期只写日志，不接外部分析服务；这些数据用于决定第二批 9 个天赋的费用和效果。

## 后续扩展门槛

只有当首个里程碑通过自动回归、半庄人工矩阵，并证明大牌、控制反制、蓄力爆发三条链路均可理解且能产生明确决策时，才进入 18 天赋扩展。第二批内容另写规格，不在本设计中预留未验证的通用脚本系统。
